# 图纸识别修订与四图回归

首次下载方案再次修订：用户两台设备均出现原始 ONNX 整包下载超时，因此原先“60 秒整包重试”已替换为同源 gzip 分块（最多 256 KiB/块，双并发）。总传输约 13 MB，模型 39 块、WASM 12 块，另有三个小资源块；每块及解压后完整文件都验证 SHA-256。已验证分块单独缓存、失败恢复时复用；网络持续有数据则不会因旧的整包 60 秒限制而重来。无数据超时与单块总时间仍有限制，防止无限等待。另提供 `.cbocr` 离线包，导入时全部校验后保存，不修改库存和图纸。已验证全新 OCR 缓存、断网导入后启动引擎及刷新，四图识别与此前结果一致。本站完全不可达仍需其他网络或从已下载文件导入，分块并不能保证所有网络可达。

加载与错位问题后续修订：用户提供的猫咪导出图为 45×45，而原始图纸坐标为 46 列×45 行。对完整原图用 45 列采样会跨格混色；新增分格宽高比异常提醒，可取消后核对，也可对拉伸图确认继续。此提醒不是自动格线检测，无法发现所有框选偏移。PNG 导出不再把空白格打印为 `null`。

`Failed to fetch` 原因需区分模型、字典和 WASM 加载，单凭导出图不能定位用户设备上的失败请求。代码中发现版本更新会删除已缓存 OCR 资源，以及缓存写入失败会使网络成功请求也报错。现已拆出持久 OCR 缓存、迁移旧缓存，缓存写失败不阻止使用下载结果；模型/字典下载最多尝试三次，并报告失败文件。模拟断网、恢复下载、升级缓存迁移和四图离线回归均纳入测试。

本次线上复测遇到首次加载超过 90 秒。进一步检查：模型与 WASM 的 HEAD 请求均返回 200，但浏览器模型下载出现连续 60 秒超时（ERR_ABORTED），因此不能宣称当前网络下线上首次加载已正常。新增按资源展示下载阶段与重试次数，并将 WASM 下载纳入同样的缓存、超时、重试逻辑。本地四图及离线测试通过；GitHub Pages 的实际网络可达性仍是外部限制。

后续库存规则更新：按用户要求，库存扣减现在优先使用已保存的底部统计。网格数量差异和问号只提示，不阻止按底部统计扣减；无底部统计时才采用网格数量，仍有问号则阻止扣减。库存不足、非法数量和重复扣减仍会拦截。下文“数量不符禁止扣减”为识别版本初次发布时的历史行为，已被本规则取代。

2026-11-07。测试使用用户提供的四张原图，人工确认网格边界和行列数，参考底部印刷数量。浏览器使用桌面 Edge 的 390×844 触屏模拟环境，并非真实手机性能测试。

四图共 37 条底部记录均匹配，无遗漏。面包的 G04 规范为 G4；G14 数量为 230。面包第 43 行第 31–36 列被水印遮挡，保留问号。风景第 3 行第 28 列的 C24 与水印交叠，保留问号，可人工确认。

本机浏览器识别约 1–6 秒/图，取决于疑难格复核次数；不代表手机性能，也不包括公网首次下载时间。模型和 WASM 约 22 MB。

逐色数量一致不能证明每个格子位置全部正确。本次另对风景图的 G1、H18、B23 问题坐标做了定点断言，尚无完整逐格人工标注，因此不宣称像素级准确率 100%。

## 修复与机制

- 底部整段 OCR 改为色卡分割，保留白色卡；分开读取色号和数量，支持括号及前导零。
- 图例色号缺失时，从同色网格取得两个一致文字读数辅助恢复。
- 底色从上传图片取样，不依赖初始库存色表的 RGB。使用主色、文字占用和近色字形比较，疑难格再做 OCR。
- 修复 G1 末位数字因裁切太窄被删除的问题。文字/底色证据不足时显示问号，不用数量倒推位置。
- 浏览器 ICC 色彩转换会影响近色取样，故必须运行浏览器回归。原始 PNG 解码测试的风景图待确认位置为第 31 行第 2 列 H18，与浏览器结果不同；同样保留 1 格问号。两种解码路径各有明确回归预期。
- 新增原图对照、图例编辑、预览高亮、定位问号、单格改色/清空/恢复；禁止未校对或数量不符的图纸扣减库存。
- 手机两次点选、图片缩放、网格分隔线；模型在 Worker 中本地执行，资源随站点提供并缓存。

## 开源方案调研

- [02528/pin-bead-helper](https://github.com/02528/pin-bead-helper)：MIT，参考其规则网格采样、避开标签中心的思路；白色直接映射某色号的假设不适用于所有图片，本项目没有采用。
- [Emma-Zhuym/pindou](https://github.com/Emma-Zhuym/pindou)：AGPL-3.0；README 的底部色号/数量方案包含可选外部视觉 API 或人工输入，不能当作完全离线 OCR 的效果证明。未复制其代码。
- [Zescy1/Red_bean](https://github.com/Zescy1/Red_bean)：参考 `grid_sampler.py` 的主色量化和文字占用思路，未复制代码。
- [RapidAI/RapidOCR](https://github.com/RapidAI/RapidOCR)、[PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)：采用 PP-OCRv4 识别模型，结合自写规则网格与色卡分割，避免对整张图片逐格执行 OCR。
- [ONNX Runtime](https://github.com/microsoft/onnxruntime)：浏览器 WASM 推理。没有添加收费 API 或图片上传服务。

## 验证范围与限制

已验证单元测试、四原图推理、真实 Worker/WASM 浏览器推理、手机尺寸无横向溢出、触屏两点框选和缩放、底部数量编辑、修格与恢复、保存重载、库存阻断、断网重载后再次识别。未在 iOS Safari 或真实低端手机验证。

当前适用清晰、轴对齐的规则网格截图和底部重复色卡布局。用户仍须正确框选、填写行列数。拍照透视、严重压缩、不同色表、复杂水印、多种未见过的图例布局仍可能失败，需要人工校对。不会为了让测试数量通过而自动凑数。
